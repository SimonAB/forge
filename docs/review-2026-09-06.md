# Integration review — 6 September 2026

The division of responsibility is clear: Forge owns project kanban, portable
sidecars carry project state, and Super Productivity owns tasks when enabled.
The weakest points are the joins between those components and the remaining
legacy task readers. This review concentrated on the recent nexus, SP, project
opening, and Reminders capture changes; it was not an exhaustive audit.

## Changes made

- **Portable metadata:** `KanbanFsSync` now compares meta tags and assignees as
  well as column names. Doctor, explicit sync in either direction, and Refresh
  use one comparison helper. Unchanged state avoids writes; tag order is ignored.
  Previously a same-column change to URGENT or assignees was silently skipped.
- **Inbox deadlines:** SP due queries include Inbox, including when the project
  listing omits that built-in project. Completed tasks remain excluded.
- **Capture completion:** the Reminders drain requires a JSON object confirming
  the SP backend and a nonempty task ID before completing the source reminder.
  Invalid responses become structured failures rather than completion or a crash.
- **Continuous checks:** CI now runs both Python unittest directories alongside
  the Swift suite, rather than only compiling the brief script.

Regression tests reproduce each fault. Tests use temporary folders, an in-memory
tag store, and fake capture/Reminders commands. No live tasks, Finder tags, or
SP state were changed during verification.

## Follow-up implementation

The four items below were addressed after the checkpoint commit `b2bb15e`:

- Dashboard now selects SP when enabled and joins tasks by mapped project ID.
- SP launch is shared, graceful, and bounded. Forge uses a persistent `.venv`;
  CLI and GUI Python entry points share the interpreter resolver.
- Python SP and board configuration now use PyYAML safe decoding, with boolean
  validation and a declared dependency file.
- Reminders capture now keeps locked, durable receipts. Confirmed captures are
  reused; uncertain captures require reconciliation. Receipts are local to one
  machine. See the recovery procedure in [Super Productivity](superproductivity.md).

Verification remains offline: app relaunches and real capture mutations have not
been exercised. The original findings follow for context.

## Original integration findings

1. **Finish the dashboard cutover.** `scripts/forge_dashboard/data.py` still reads
   `tasks.db` even when SP is enabled. Its inbox and due strip can disagree with
   capture and briefs. This is already listed as planned in
   [Super Productivity](superproductivity.md). A shared task-query interface
   would keep the brief and dashboard on the same backend.
2. **Make SP project opening durable.** `SuperProductivityFocus.swift` prefers
   `/tmp/sp-cdp-venv`, while `forge-sp-focus-project.py` can force-kill SP when CDP
   is unavailable. Move the dependency to a durable installation and replace
   force-kill with a bounded, graceful launch sequence. This needs a deliberate
   app lifecycle test; the current review did not exercise live relaunches.
3. **Unify configuration parsing.** Swift uses Yams, but the SP Python adapter
   parses a small YAML subset by hand. For example, `enabled: false # comment`
   becomes a truthy string in Python. Quoted project names containing colons also
   need proper parsing. Use one supported parser or a decoded CLI configuration
   export rather than extending several independent parsers.
4. **Make capture retries idempotent.** If SP capture succeeds but completing the
   reminder fails, a later drain can create a duplicate. The completion gate
   fixed here prevents unconfirmed completion; a durable source-ID receipt is
   still needed to reconcile partial success across runs.
